# 编码体系

> **对应考点**：ISCC 2026 密码安全赛 模块 1「经典密码基础」第 2 条 ——
> **常用编码变换与多层编码识别**
>
> **一句话本质**：编码不提供任何保密性，它只是换一种写法。所以编码题的难度**永远不在算法，而在"认出是哪一层"**。
> 认出来 → 一行代码；认不出 → 猜一小时。

---

## 0. 判别总纲

### 0.1 先判：这是编码还是密码？

| 特征 | 倾向 |
|---|---|
| 字符集固定且"看起来像某种字母表" | **编码** |
| 长度符合某个整除/膨胀关系 | **编码** |
| 字母频率分布仍接近自然语言（IC≈0.065） | **密码**（单表替换/凯撒） |
| 字母分布平坦（IC≈0.038） | **密码**（多表/维吉尼亚） |
| 直接解一次就出明文 | 编码 |

### 0.2 三层剥离法

```
第 1 层：结构性痕迹（%, &#, \u, =, begin 644）   ← 肉眼可见，先剥
第 2 层：字符集判据（字母表长什么样）              ← 本篇 §1–§4
第 3 层：解出来仍是乱码 → 可能是编码套密码        ← 转去 古典密码1.md
```

**铁律：每剥一层，立刻检查一次"是否已可读"。** 不要连续剥三层再回头看——剥过头会把明文又"编码"回乱码。

## 1. base 家族

### 1.1 核心原理（一句话）

把字节流按位数重新切分，每 N 位映射到字母表里的一个字符。

| 变体 | 每字符携带 | 字符集 | 膨胀率 | 填充 |
|---|---|---|---|---|
| base16 (hex) | 4 bit | `0-9A-F` | 2.0 | 无 |
| base32 | 5 bit | `A-Z2-7` | 1.6 | `=` |
| base64 | 6 bit | `A-Za-z0-9+/` | 1.33 | `=` |
| base64url | 6 bit | `A-Za-z0-9-_` | 1.33 | 常省略 |
| base85 / Ascii85 | 6.4 bit | 大量可打印符号 | 1.25 | 无 |
| base91 | 6.55 bit | 91 个符号 | 1.23 | 无 |

### 1.2 判据：看字符集，不要看长度

| 观察 | 结论 |
|---|---|
| 只有 `0-9A-F`（可能带空格/`0x`） | base16 / hex |
| 只有 `A-Z` 和 `2-7`，末尾有 `=` | base32 |
| 含 `+` `/`，末尾有 `=`，长度是 4 的倍数 | base64 |
| 含 `-` `_` 而不是 `+` `/` | base64url |
| 含大量 `!`–`u` 的可打印符号，无 `=` | base85 |
| 字符高度混杂、含引号反斜杠等 | base91 |

### 1.3 三个高频坑

**坑 1：长度不是 4 的倍数 → 补 `=` 再解**
```python
s = s + "=" * (-len(s) % 4)
```

**坑 2：换表 base64（自定义字符表）**
题面给一张 64 字符的置换表。做法：把密文字符映射回标准表的索引，再按标准 base64 解。
→ 现成脚本 `crypto/19-basemap.py`（按自定义表查回 6 bit，拼位流切 8 bit）

**坑 3：base64 字符集是 hex 的超集**
纯 hex 串也能被 `b64decode` 不报错地解出垃圾字节。**判据不是"能不能解"，而是"解出来是不是可打印"**。

### 1.4 常用命令

```python
import base64
base64.b64decode(s)        # 标准
base64.urlsafe_b64decode(s)  # -_ 变体
base64.b32decode(s)
bytes.fromhex(s)             # base16
```

## 2. URL / HTML / Unicode 转义

**共同特征**：有明显"结构残留"。看到这些符号，先按转义处理，不要当密码。

| 形式 | 样例 | 处理 |
|---|---|---|
| URL 百分号 | `%7B%22` | `urllib.parse.unquote` |
| HTML 实体 | `&#x7B;` `&amp;` `&lt;` | `html.unescape` |
| Unicode 转义 | `\u007b` | `bytes.decode('unicode_escape')` |
| JS 八进制/十六进制 | `\x7b` `\173` | 手工替换或 `codecs` |
| 双重 URL 编码 | `%257B` | 连续 unquote 两次 |

**坑**：`+` 在 URL 编码里代表空格，但 `unquote` **不会**自动转。表单场景要先 `s.replace('+',' ')`。

## 3. 摩斯密码

**难点不在对照表，在分隔符被改写。**

| 题目形态 | 判据 | 处理 |
|---|---|---|
| 标准 | `.` `-` + 空格分字母 + `/` 分单词 | 直接查表 |
| A/B 代替 | 只有两种字符，且成组出现 | `A`→`.`、`B`→`-` 再解 |
| 0/1 代替 | 同上 | `0`→`.`、`1`→`-` |
| 分隔符混乱 | 空格数量不一 | 先统计，再试"单空格=字母、双/三空格=单词" |
| 无分隔符 | 一条连续的点划串 | 做 DFS 分词（多解，用英文词频/flag 格式筛） |

→ 现成脚本：`crypto/04-培根与摩斯.py`

**自检**：解出的明文应当全是大写字母/数字/常见标点；出现大量非常规组合说明分隔符判错。

## 4. 冷门编码

> 判断原则都一样：**看字符集是否只落在一个极小的固定集合里**。

### 4.1 键盘位移（QWERTY 错位）

**判据**：密文全是字母，读不通，且每个字母在键盘上都是相邻键。
规则、三种位移变体、全位移暴力 → 独立篇 `冷门编码.md` §1。

### 4.2 T9 / 手机九宫格

`2=ABC 3=DEF 4=GHI 5=JKL 6=MNO 7=PQRS 8=TUV 9=WXYZ`
多击 / 单数字 / 分隔符三种写法、组合爆炸与词表筛 → `冷门编码.md` §2。

### 4.3 社会主义核心价值观编码

**判据**：全文只由这 12 个词（24 个字）组成 ——
`富强 民主 文明 和谐 / 自由 平等 公正 法治 / 爱国 敬业 诚信 友善`

> ⚠️ **这里原先写错了两条，已纠正**：
> ① 不是"每个半字节 → 一个词"。`0–9` 映射 **1 个**词，`a–f` 映射 **2 个**词（两种拆法随机）；
> ② 长度**不是**固定的 2 的倍数。真实规律：**词数 = 2×字节数 + 其中 a–f 的个数**。
>
> 完整词表顺序、两张拆分对照表、可跑编解码 → `冷门编码.md` §3（已用真实世界样例反解验证）。

### 4.4 其他一眼可认的

| 编码 | 判据 | 备注 |
|---|---|---|
| uuencode | 以 `begin 644` 开头、每行以 `M` 开头 | 老邮件附件格式 |
| XXencode | 字符集 `+-0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz` | 与 uuencode 类似 |
| JSFuck | 只有 `[ ] ( ) ! +` 六种字符 | 交给浏览器执行 |
| Jother | 只有 `! + ( ) [ ] { }` | 同上 |
| 颜文字编码 | 由固定几个表情符号组成 | aaencode/JS 变体 |
| 猪圈密码 | 图形化，井字/叉字格 | 需要图，非纯文本 |

## 5. 多层嵌套的标准流程

```
① 看整体：把密文丢进编码自动识别，看它给出什么
        py misc/01-编码自动识别与解码.py
② 若识别出多层：从外到内逐层剥，每层记录一次
③ 每层剥完做三件事：
   · 是否可打印（可打印率 > 90%？）
   · 是否含 flag 格式（flag{ / CTF{ / 题目指定前缀）
   · 是否仍是"纯字符集"（还是编码）
④ 若剥离后仍乱码且字符集是 26 字母 → 转 古典密码1.md（密码层）
```

**自检脚本**

```python
def printable_ratio(b: bytes) -> float:
    ok = sum(1 for x in b if 32 <= x < 127 or x in (9, 10, 13))
    return ok / max(len(b), 1)

# 判据：> 0.9 认为是"已解出可读文本"
```
