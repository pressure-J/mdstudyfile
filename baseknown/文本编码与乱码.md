# 文本编码与乱码

## 一、为什么需要"编码"

计算机只存**字节**(0/1),不存"字符"。要让计算机认识 `A`、`中`、`😀`,必须有一套**映射规则**:字符 ↔ 字节序列。这套规则就叫**字符编码(Character Encoding)**。

同一个字符,用不同编码规则得到的字节可能完全不同;同一串字节,用不同编码解释出来的字符也可能完全不同——**乱码的根源就在这里**。

---

## 二、先分清两个概念

- **字符集(Charset)**:有哪些字符,每个字符对应一个编号(**码点 / Code Point**,如 `中` = U+4E2D)。
- **编码(Encoding)**:把码点变成字节的具体规则(如 UTF-8 把 U+4E2D 编成 `E4 B8 AD`)。

> 例:`中` 的码点是 U+4E2D,UTF-8 编码后是 `E4 B8 AD`,GBK 编码后是 `D6 D0`。**同一个字,不同编码,不同字节。**

---

## 三、常见编码

| 编码 | 字节长度 | 范围/特点 |
|---|---|---|
| **ASCII** | 1 字节 | 只含 0-127(英文、数字、标点),最高位恒为 0 |
| **Latin-1 / ISO-8859-1** | 1 字节 | 0-255,单字节"万能兜底",任意字节都能解(不会报错) |
| **GB2312 / GBK / GB18030** | 变长(1-2/4) | 中文国标,GBK 兼容 GB2312,GB18030 超集 |
| **UTF-8** | 变长(1-4) | 兼容 ASCII,英文 1 字节、中文 3 字节、emoji 4 字节,现在最主流 |
| **UTF-16** | 2 或 4 字节 | Windows 内部常用,分 **LE(小端)/ BE(大端)** |

**UTF-8 的字节规律(重要)**

| 首字节 | 含义 |
|---|---|
| `0xxxxxxx` | 单字节(ASCII,和 ASCII 完全一样) |
| `110xxxxx` | 双字节的首字节 |
| `1110xxxx` | 三字节的首字节(中文在这) |
| `11110xxx` | 四字节的首字节(emoji 在这) |
| `10xxxxxx` | 后续字节(续字节) |

**兼容性要点**:ASCII ⊂ UTF-8;所以纯英文文本用 ASCII 和 UTF-8 存出来一模一样,这也是 UTF-8 能迅速普及的原因。

---

## 四、BOM(字节顺序标记)

BOM 是**放在文件开头的几个特殊字节**,用来标明"这是什么编码、什么字节序":

| 编码 | BOM(hex) | 说明 |
|---|---|---|
| UTF-8 | `EF BB BF` | UTF-8 本无字节序问题,BOM 只为标识"我是 UTF-8" |
| UTF-16 LE | `FF FE` | Windows 记事本默认 |
| UTF-16 BE | `FE FF` | |
| UTF-32 LE | `FF FE 00 00` | |
| UTF-32 BE | `00 00 FE FF` | |

**要点**
- BOM 可以看作一种"特殊魔数",出现在文件最开头。
- 有些程序(尤其 Linux 工具)不认 BOM,会把 `EF BB BF` 当成正文显示成乱码 `锘`。
- Windows 记事本"UTF-8"默认带 BOM(旧版),VS Code 默认不带——这常导致跨平台乱码。

---

## 五、换行符(也是编码差异)

| 系统 | 换行符 | hex |
|---|---|---|
| Windows | CRLF(`\r\n`) | `0D 0A` |
| Linux / macOS(新) | LF(`\n`) | `0A` |
| 老 Mac | CR(`\r`) | `0D` |

跨平台传文件时换行符不一致,可能导致脚本报错、显示多空行。Git 有 `core.autocrlf` 自动转换。

---

## 六、乱码是怎么产生的

**核心公式:用编码 A 存,却用编码 B 读。**

### 常见乱码现象

| 现象 | 原因 |
|---|---|
| **娴嬭瘯** 这类"繁体字乱码" | UTF-8 存的字节,被当 **GBK** 读 |
| **Ã¤Â¸Â** 这类带符号乱码 | UTF-8 存的字节,被当 **Latin-1** 读 |
| **锟斤拷** | 连续出现多个 `EF BF BD`(U+FFFD 替换字符),被当 GBK 读:EFBF→锟、BDEF→斤、BFBD→拷 |
| **烫烫烫** | MSVC 调试模式用 `0xCC` 填充未初始化内存,`CC CC` 在 GBK 里 = 烫 |
| **屯屯屯** | 同上,填充 `0xCD`,`CD CD` 在 GBK 里 = 屯 |
| **口口口 / 方块** | 字节是 `00` 或无法显示,渲染成方块 |

### 例子走一遍

```
"测试" 用 UTF-8 编码 → E6 B5 8B E8 AF 95
                  ↓ 用 GBK 解码
              E6B5→娴  8BE8→嬭  AF95→瘯   → 显示 "娴嬭瘯"(乱码)

"测试" 用 GBK 编码 → B2 E2 CA D4
                  ↓ 用 UTF-8 解码(非法字节序列)
              → 报错,或显示 "�"(U+FFFD)
```

> 记忆:乱码能不能"救回来",取决于**原始字节有没有丢**。只是"解码用错",字节还在,换对编码就能还原;如果已经被 `�` 替换(有损),就救不回来了。

## 七、怎么判断和修复乱码

**判断顺序**
1. **看 BOM**:开头 `EF BB BF` → UTF-8;`FF FE` → UTF-16 LE
2. **看字节规律**:大量 `E4-E9` 打头的三字节组 → 像 UTF-8 中文
3. **用工具猜**:`chardet`(Python)、浏览器"自动检测编码"、VS Code 右下角切换编码
4. **暴力试**:用几种编码轮流 `decode`,哪种不报错且是正常文字就用哪种

**Python 处理**
```python
b = open('data.bin','rb').read()          # 先按原始字节读
for enc in ['utf-8','gbk','gb18030','big5','latin-1']:
    try:
        print(enc, '=>', b.decode(enc)[:50])
    except UnicodeDecodeError:
        print(enc, '=> 解码失败')
```

**常见修复思路**
- 乱码是"UTF-8 被当 GBK 读"→ 用 **GBK 编码回去**得到原字节,再用 **UTF-8 解码**:
```python
s = '娴嬭瘯'.encode('gbk').decode('utf-8')   # → '测试'
```
- 反之亦然。**"编码回去 → 换编码解码"是修复乱码的通用招式。**

**Python 的 errors 参数**
```python
b.decode('utf-8', errors='ignore')   # 丢弃非法字节
b.decode('utf-8', errors='replace')  # 换成 � (U+FFFD)
b.decode('utf-8', errors='strict')   # 默认,报错
```

## 八、零宽字符隐写(CTF 高频)

有些 Unicode 字符**不可见**,能藏在正常文本里传信息:

| 字符 | 码点 | UTF-8 字节 | 用途 |
|---|---|---|---|
| 零宽空格 ZWSP | U+200B | `E2 80 8B` | 隐写常用 |
| 零宽不连字 ZWNJ | U+200C | `E2 80 8C` | |
| 零宽连字 ZWJ | U+200D | `E2 80 8D` | emoji 组合也用 |
| 字节序标记 ZWNBSP | U+FEFF | `EF BB BF` | 同 UTF-8 BOM |

**识别**:文本看起来正常,但复制出来长度不对;用十六进制看会发现夹着 `E2 80 8B` 之类的字节。把 0/1 映射成这些零宽字符就能藏一段二进制。

---

## 九、CTF 相关应用

| 场景 | 要点 |
|---|---|
| 乱码还原 | "编码回去 → 换编码解码" |
| BOM 混入 | 开头的 `EF BB BF` 可能是干扰或标志 |
| 零宽字符 | 用 hex 查看,提取不可见字符 |
| 同形字 | 形近字符(如拉丁 `a` vs 西里尔 `а`)伪造域名/文本 |
| 编码套娃 | Base64 → UTF-8 → GBK … 层层解 |
| 摩斯/培根 | 文本类编码,配合工具箱 `crypto` 分类 |


## 十一、要点总结

1. 计算机只存字节,编码是"字符 ↔ 字节"的映射规则。
2. 字符集(有哪些字符)和编码(怎么变字节)是两回事。
3. 常用:ASCII、Latin-1、GBK/GB18030、UTF-8、UTF-16(LE/BE)。
4. UTF-8 兼容 ASCII;中文 3 字节、emoji 4 字节。
5. **BOM** 是文件开头的编码标识:`EF BB BF` = UTF-8,`FF FE` = UTF-16 LE。
6. 换行符:Windows `0D 0A`,Linux `0A`。
7. **乱码 = 用 A 编码存、用 B 编码读**;字节没丢就能救,`�` 出现就是有损。
8. 修复招式:**编码回去 → 换编码解码**。
9. 零宽字符(U+200B 等)是常见隐写手段。
10. 判断编码:看 BOM → 看字节规律 → 工具猜 → 暴力试。
