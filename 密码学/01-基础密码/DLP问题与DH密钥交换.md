# 离散对数问题（DLP）

## 一句话

**已知 $g$ 和 $h$，求指数 $x$ 使 $g^x \equiv h$。** 正向算幂很快（快速幂，$O(\log x)$ 次乘法），反向求指数很慢，这就是单向性的来源。

## 前提：群、生成元、阶

| 概念     | 含义                                                      | 例子（模 11 乘法）                                           |
| -------- | --------------------------------------------------------- | ------------------------------------------------------------ |
| 群       | 一个集合 + 一个运算，满足**封闭、结合、有单位元、有逆元** | $(\mathbb{Z}/11\mathbb{Z})^*=\{1,2,\dots,10\}$，阶 $|G|=10$  |
| 元素的阶 | $g$ 自己乘多少次回到单位元                                | 底 3：$[3,9,5,4,1]$ → 阶 5                                   |
| 生成元   | 幂序列能把全群踩一遍的元素                                | 底 2：$[2,4,8,5,10,9,7,3,6,1]$ → 阶 10，是生成元             |
| 循环群   | 存在生成元的群                                            | $(\mathbb{Z}/11)^*$ 是；$(\mathbb{Z}/8)^*=\{1,3,5,7\}$ **不是**（每个元素阶都只有 2） |

要点：**离散对数只在循环群上才有唯一解**（解唯一确定到 $\mathrm{mod}\ n$）。非循环群里问题会变成"无解或多解"，那不是难，是定义不了。

## 实例

```python
p, g, x = 23, 5, 6
h = pow(g, x, p)      # 正向：h = 8，秒出
# 反向：已知 p=23, g=5, h=8，求 x → 只能挨个试
```

## 难度由「群」决定，不是由方程决定

| 群                           | 额外结构                 | 最优攻击                                     | 实用参数  |
| ---------------------------- | ------------------------ | -------------------------------------------- | --------- |
| $(\mathbb{Z}/p\mathbb{Z})^*$ | 能提升回整数环做光滑分解 | Index Calculus（**亚指数**）                 | 3072 位起 |
| $(\mathbb{Z}/2^k)^*$         | 2-adic 对数、非循环      | 按位求解（**多项式**）                       | 不能用    |
| 椭圆曲线 $E(\mathbb{F}_q)$   | 没有可利用的额外结构     | Pollard ρ（$O(\sqrt{q})$，是下界也是天花板） | 256 位够  |

→ 所以 **ECC 用 256 位就顶 RSA 3072 位**：不是它更复杂，而是它"结构贫瘠"，任何捷径都不存在。
→ 模 2 的幂那道题（见 `模2的幂-离散对数.md`）能秒解，就是因为它落在第二行。

## DLP ≠ 大整数分解

| 难题       | 难在哪                                          | 会不会被"换群"影响             |
| ---------- | ----------------------------------------------- | ------------------------------ |
| 大整数分解 | 乘法混得开、除法分不开（$n=pq$ 回推不出 $p,q$） | 不变，题目固定                 |
| 离散对数   | 指数混得开、数不出步数                          | **会**，难度完全取决于选哪个群 |

RSA 的"$e$ 次方好算、开 $e$ 次方难"形式像 DLP，但一旦分解 $n$ 就能用 CRT 直接算出私钥 $d$——它难在**分解**，不在"指数未知"。

# DH 密钥交换（Diffie–Hellman）

## 解决什么问题

对称加密（AES 等）效率高，但双方得先有同一个密钥；而任何"传密钥"的动作都会被窃听。DH 让**双方在不安全的信道上算出一个只有他俩知道的密钥**，全程不传输密钥本身。

## 流程（一句话版）

双方各自藏一个随机数，公开"藏起来的数的幂"，然后拿对方的幂自乘自己那个数——两边凑出同一个值。

```
公开参数：大素数 p、生成元 g（明文广播，谁都能看）

Alice                          Bob
选私钥 a（保密）                 选私钥 b（保密）
A = g^a mod p    ──发送 A──→
                 ←─发送 B───    B = g^b mod p
K = B^a mod p                   K = A^b mod p
        ↓                              ↓
   K = (g^b)^a = g^(ab)        K = (g^a)^b = g^(ab)     ← 同一个 K
```

## 为什么成立（就一步代数）

$$K = B^a = (g^b)^a = g^{ab} = (g^a)^b = A^b$$

指数可以交换相乘，这就是它能"各算各的却算出同一个数"的全部原因。

## 真实数据

```python
p, g = 23, 5
a, b = 6, 15              # 两人各自保密
A, B = pow(g,a,p), pow(g,b,p)   # A=8, B=19，走明信道
K1, K2 = pow(B,a,p), pow(A,b,p) # 都是 2
```

窃听者手上只有 $p=23,\ g=5,\ A=8,\ B=19$，要解密就得先解 $5^a\equiv 8 \pmod{23}$ —— 这正是 **DLP**。

## 安全性与前提

| 项             | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| 依赖难题       | **CDH**（Computational DH）：由 $g^a,g^b$ 算出 $g^{ab}$ 难；CDH 不会比 DLP 更难 |
| 参数要求       | $p$ 至少 2048/3072 位；$p-1$ 必须含大素因子（否则 Pohlig–Hellman 拆解）；$g$ 应落在**大素数阶子群**里 |
| 必须拦         | 小阶子群攻击：攻击者伪造 $B'$ 为小阶元素，反复试探能把 $b$ 模小素数算出来 → 现代实现要求校验公钥阶、有 NIST 安全素数 |
| 无认证         | **DH 本身不验证对方身份**，可被中间人（MITM）完全接管：攻击者对 Alice 冒充 Bob、对 Bob 冒充 Alice，两段 DH 各自成立 → 实践中必须配签名/证书（即 STS、TLS 里的 ECDHE + 证书） |
| 也要防离线爆破 | 纯 DH 得到的 $g^{ab}$ 是群元素不是随机串，得先过 KDF 再用    |

## 变体与延伸

- **ECDH**：把群换成椭圆曲线，256 位即可，TLS 1.3 默认就是 ECDHE。
- **DHE / ECDHE**：每次会话现生成 $a,b$，即"临时密钥"，提供**前向保密**（长期私钥泄露也解不开历史流量）。
- **ElGamal**：把 DH 的"算共享密钥"改成"直接加密"，$C_1=g^k,\ C_2=m\cdot h^k$。
- **Schnorr**：把 DH 的"各自幂"改成"承诺 + 挑战 + 响应"，可得零知识证明与签名（见 `04-其他/Schnorr协议.md`）。

## DH、Schnorr、ECC 的关系（最容易混的一点）

| 名词         | 是什么                        |
| ------------ | ----------------------------- |
| DLP          | 一个**难题**                  |
| ECC          | 一个**群**（承载 DLP 的地方） |
| DH / Schnorr | 一个**协议**（把 DLP 用起来） |

所以"Schnorr、DH、ECC 都基于离散对数"这句话里，三者并不在同一层——**协议决定怎么用，群决定难不难**。
