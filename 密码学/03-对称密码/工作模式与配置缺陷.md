# 工作模式与配置缺陷

> **一句话本质**：分组密码只定义了「16 字节 → 16 字节」，加密长消息靠工作模式；**算法再强，模式配错全白搭**——考题九成出在模式层，而不是算法层。
> 对应综述路径③；Padding Oracle 单独成篇 →《填充与Padding-Oracle》（待写）。

---

## 0. 加密全流程（顺序是死的：先填充，后切块）

```
明文 → ① 填充(PKCS#7) 补到 16 的倍数 → ② 切 16 字节块 → ③ 逐块过模式加密 → 密文
解密反向：解密 → 拼回 → 看末字节 n → 剥掉 n 个填充字节
```

PKCS#7 两条规则（2026-10-22 我才知道"刚好整倍也要补"）：
- **填充值 = 补的个数**：补 9 个就全是 `\x09`；明文刚好 16 倍数 → **补一整个 16 字节块**（不补则解密端分不清末尾 `\x01` 是数据还是填充）
- CTR/OFB 等流式模式**不填充不切块**——明文多长 XOR 多长，**密文长度 = 明文长度**（这也是识别模式的线索）

---

## 1. 五种模式：加密/解密递归全流程

> 记号约定：$E_K(\cdot)$ = 分组加密（黑盒，从不需要打开）；$D_K(\cdot)$ = 解密 = $E$ 的逆；
> 明文块 $P_1, P_2, \ldots$（$P_0$ 不存在），密文块 $C_1, C_2, \ldots$，IV/nonce 题面会给。
> **读法**：每个模式先看「递归式」——$i$ 项靠 $i-1$ 项（或计数器 $i$）算出来，这就是"链条"或"流"的来源；链条怎么搭，决定它怎么塌。

### ECB —— 没有链条（每块独立）

```
加密：C_i = E_K(P_i)                    i = 1, 2, 3, ...
解密：P_i = D_K(C_i)                    与别的块无关，顺序乱了解密照样对
```

**递归在哪**：没有。块与块之间零耦合——这正是"电子密码本"：一个 16 字节 → 16 字节的查找表，明文同则密文同。
**为什么塌**：独立意味着可替换。任何一块密文挪到别处，解密端照常还原——题 A 的块拼接就是把 trudy 的 `role` 块插进 carol 的记录，链条越松越好拼。
**解密需要**：$D$。

### CBC —— 密文链条（上一块密文喂进下一块）

```
加密：C_i = E_K(P_i ⊕ C_{i-1})          其中 C_0 = IV
解密：P_i = D_K(C_i) ⊕ C_{i-1}          其中 C_0 = IV
```

**递归怎么滚**：加密第 $i$ 块前，先把上一块**密文** $C_{i-1}$ 拌进明文（$P_i \oplus C_{i-1}$）再加密。链条是 $IV \to C_1 \to C_2 \to \cdots$，所以同样的 $P_1$ 配不同 IV，$C_1$ 起全盘不同——ECB 的重复块病被治好了。
**解密为什么快**：$D_K$ 是逐块并行的，$\oplus C_{i-1}$ 只是补一步——所以解密比加密更可并行。
**为什么塌（比特翻转）**：解密端 $P_i$ 里的 $C_{i-1}$ 是**从密文里原样拿的**，不经过任何校验。攻击者改 $C_{i-1}$ 的一个比特：$D_K(C_{i-1})$ 那块炸成随机垃圾，但 $P_i = D_K(C_i) \oplus C_{i-1}$ 里对应比特**精确翻转**。改"上一块"= 改"下一块明文"的遥控器。
**解密需要**：$D$（逐块）。

### CFB —— 密文喂进寄存器，密码只出密钥流

```
加密：O_i = E_K(I_i)                    I_1 = IV
      C_i = P_i ⊕ O_i                   ← 明文只做 XOR，不进 E
      I_{i+1} = C_i                     (CFB128；窄版 CFB8 是移位寄存器左移)
解密：O_i = E_K(I_i)，P_i = C_i ⊕ O_i    I 同样从密文取
```

**递归怎么滚**：寄存器 $I$ 初始装 IV；每轮把 $I$ 加密出 $O_i$ 当密钥流用掉，然后把**密文 $C_i$ 装回寄存器**。流化的关键：$E$ 只作用于寄存器，明文永远只做 XOR。
**为什么塌（IV 重用）**：寄存器初值相同 + 密文流不参与第一轮之前的状态 → 两条消息的 $O_1$ 相同；若明文相同则密文相同、寄存器继续同步，**密钥流逐块重演**。同 key 同 IV 两条消息 → $M_2 = C_1 \oplus C_2 \oplus M_1$ 照打。
**与 OFB/CTR 的区别（篡改放大）**：$C_i$ 参与反馈 → 改 $C_i$ 一位，寄存器变，$O_{i+1}$ 起全变，后面**明文全崩**（OFB/CTR 改一位只错一位）。CFB 自带"防篡改放大镜"，这是它独立考点。
**解密需要**：**只用 $E$**（收发双方都只跑加密方向）。

### OFB —— 密钥流自我迭代，与明文密文都无关

```
加密：O_1 = E_K(IV)
      O_i = E_K(O_{i-1})                ← 密钥流自己迭代自己
      C_i = P_i ⊕ O_i
解密：同样先造 O 序列，P_i = C_i ⊕ O_i
```

**递归怎么滚**：$O$ 序列是一条**独立于明文和密文的纯密钥流**——$O_1$ 由 IV 定，$O_2$ 由 $O_1$ 定……整个序列在加密开始前就能全部算完。分组密码在这里退化成一台"流密码机"。
**为什么塌（IV 重用）**：序列只由 key+IV 决定 → 同 key 同 IV = 同一条密钥流用两遍 = 一次性密码本的钥匙抄两份。B2 题的全流程：PNG 头 29 字节 crib → 恢复 $O_1$ 的前 29 字节 → 直接 XOR 出 27 字节的 msg。
**为什么错误不扩散**：$O$ 序列与密文无关 → 密文改一位只影响对应一位明文（与 CFB 相反）。
**解密需要**：**只用 $E$**。

### CTR —— 密钥流来自计数器，各块可并行

```
加密：O_i = E_K(Nonce ‖ counter_i)      counter_i = IV, IV+1, IV+2, ...（逐块 +1，大端）
      C_i = P_i ⊕ O_i
解密：同样再造 O 序列，P_i = C_i ⊕ O_i
```

**递归怎么滚**：和 OFB 一样"先造密钥流再 XOR"，区别只在密钥流的来源——OFB 是链式迭代（要算 $O_i$ 必须先算 $O_{i-1}$），CTR 的每个 $O_i$ 只依赖 counter 值 $i$，**互相独立、可并行、可随机访问**（直接跳到第 100 块，不用算前 99 块）。这是 CTR 成为工程默认的原因。
**为什么塌（nonce 重用）**：同 key 同 nonce → $O_i$ 序列一字不差 → B1 的 $M_2 = C_1 \oplus C_2 \oplus M_1$。错误不扩散，同 OFB。
**解密需要**：**只用 $E$**。

### 五种一句话总纲

| 模式 | 递归的"链"是什么 | 链条断/重用时的死法 |
|---|---|---|
| ECB | 无链 | 结构泄露、块可换 |
| CBC | 密文链 $C_{i-1}$ 拌进明文 | 比特翻转遥控下一块 |
| CFB | 密文链装进寄存器 | IV 重用塌 + 篡改放大 |
| OFB | 密钥流自迭代链 | IV 重用塌（错误不扩散）|
| CTR | 无链（计数器并行）| nonce 重用塌（错误不扩散）|

### 攻击要点（每模式的"怎么打"）

**ECB 攻击手册**（题 A 实战）：
1. 画 16 列对齐表（每条记录的明文按块切好）
2. **密文相等 ⇔ 明文相等**——不用密钥就能对账出"哪块内容一样"
3. 逐块指认来源，拼接伪造，脑内拼读验证成句
- 攻击者全程没有解密；块内容的三个来源全是明牌：题面格式、填充规则、ECB 相等对账
- 坑：字段不等长 → 块边界错位 → 拼出 `deptinance` 这种烂句。**每块必须来自"明文对齐位置"相同的记录**

**CBC**：IV 可预测/可控 = 同层考点（IV 可控就能对第一块做任意翻转）；填充错误有可观察行为 → Padding Oracle（另篇）。

**重用攻击通用公式（CFB / OFB / CTR 通用，今日题 B1/B2 实战）**：
密钥流由 key + IV/nonce 唯一决定，与明文无关；同 key 同 IV/nonce 加密第二条消息 = 密钥流一字不差重来。

$$C_1 = M_1 \oplus KS,\quad C_2 = M_2 \oplus KS \;\Rightarrow\; M_2 = C_1 \oplus C_2 \oplus M_1$$

KS 消失的原因：XOR 自反 $x \oplus x = 0$。**通用定理**：塌法与底层算法无关——AES、SM4、RC4 一样塌，重用类攻击不碰算法实现。

**依据**：NIST SP 800-38A 与 GM/T 0002（SM4 标准附录 A）定义的五种模式 = **ECB / CBC / CFB / OFB / CTR**。

### 模式对比表（考前扫一眼，五种全）

| 模式 | 填充 | 相同块泄露 | 可篡改 | 重用敏感 | 识别特征 |
|---|---|---|---|---|---|
| ECB | 要 | **是（命门）** | 块级挪拼 | 无所谓 | 密文有重复 16 字节段 |
| CBC | 要 | 否 | 比特翻转 | IV 重用 | 需 IV |
| CFB | 不要 | 否 | 改一位**后面全崩** | **IV 重用=死** | 流式，需 IV |
| CTR | **不要** | 否 | XOR 任意改 | **nonce 重用=死** | 密文长度=明文长度 |
| OFB | **不要** | 否 | XOR 任意改 | **IV 重用=死** | 同上 |

五种里流化的是 CFB/CTR/OFB **三个**（ECB/CBC 是纯分组处理），**重用敏感也是这 3 个**；解密只需加密方向 $E$ 的同样是这 3 个——考点记忆抓这条线。另：现实工程还有 GCM（= CTR + 认证标签，AEAD 模式），ISCC 工程应用题可能提到，记住"GCM 继承 CTR 的重用死法（nonce 重用=灾难）"即可。

## 2. 已知明文从哪来（crib 的三个来源）

1. **完整已知**：题面直接给（B1 的 msg1）
2. **格式知识**：公开文件规范 = 公开常识（B2 的 PNG 头）。**PNG 前 29 字节固定**：magic `89504e470d0a1a0a` + IHDR 长度 `0000000d` + `IHDR` + 宽高各 4B 大端 + `0802000000`；第 29 字节起是 CRC（逐文件不同，未知）
3. **可读性猜**：`flag{`、`user=`、日期头……

**考场挖固定位的方法（不背表）**：本地用 Python 造两个同参数、不同内容的文件并排 hex 对比，差异位 = 变化位，剩下就是固定位。见 `B2_png_header_ref.py`。

**长度定理**：已知明文 29 字节 → 密钥流恢复 29 字节 → **最多解出 29 字节的另一条密文**。恢复量 ≤ 已知明文量。B2 出题人把 msg2 卡在 27 字节，就是卡这个尺寸。

## 3. 诊断手册（今天踩坑换来的）

- **XOR 攻击输出乱码** → 第一步查**已知明文假设**对不对，第二步才查代码。方法对了假设错了，照样满屏乱码（B1 我把明文素材记串，全是乱码）
- **术语**：`xor(c1, m1)` 得到的是**密钥流 keystream**，不是 key。key/nonce 在重用题里**自始至终不需要恢复**。看到"recover the key"先分清它指密钥还是明文
- **分类**：信息来自公开规范 = **已知明文攻击 KPA**（crib）；信息来自系统运行行为（报错/耗时/功耗）= Oracle / 侧信道。ISCC 大纲里是模块 2 和模块 7 两回事，别混

## 5. 学到什么算过关 + 30 秒自查

**过关线**：拿到密文先切块找重复；见"同 key 同 IV/nonce"秒想到密钥流重用；能不看模板独立写出三行 XOR 恢复；能说出每个模式"为什么"能被攻击。

| 现象 | 先想 |
|---|---|
| 密文有重复块 | ECB 块重排 |
| 同 key 同 IV/nonce 两条密文 | 重用，`M2=C1⊕C2⊕M1` |
| 只知部分明文/文件头 | crib，恢复量≤已知量 |
| 改密文一位明文跟着变 | CBC 比特翻转 / XOR 可篡改 |
| 解密报错行为可观察 | Padding Oracle（另篇） |
