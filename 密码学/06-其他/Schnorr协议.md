# Schnorr协议

交互式零知识证明协议（Zp* 原始形式，课件版本），用于"证明我知道私钥"而不泄露私钥。是 Ed25519、比特币 Taproot 签名的原型。

## 系统参数

- 大素数 p = 2q+1（p、q 都是素数），阶为 q 的生成元 g
- 私钥 x ∈ Zq，公钥 y = g^x mod p
- 安全性基础：**离散对数难题**（知道 y、g 反推 x 不可行）
- 群的核心性质：g^a · g^b = g^(a+b)（同底数指数相加）

## 四步流程

1. **承诺**（A→B）：A 随机选一次性 r ∈ Zq，发 t = g^r mod p
2. **挑战**（B→A）：B 随机生成 c ∈ Zq
3. **响应**（A→B）：A 算 s = r + c·x mod q 发给 B
4. **验证**（B）：接受 iff g^s ≡ t·y^c (mod p)

验证为什么通过（完备性）：

```
t · y^c = g^r · (g^x)^c = g^r · g^(c·x) = g^(r + c·x) = g^s  ✓
```

## 核心思想：把私钥掺进随机数

s = r + c·x 是一次一填充式的混合：
- **一个方程两个未知数**（r、x 都是 B 没有的）→ 单组 (t,c,s) 推不出 x，截获全部三轮也没用
- **c 由 B 随机出** → A 选 r 时不知道 c，没法针对挑战配一个不含真 x 的假 s

零知识 = B 验证通过了，却没得到任何能算出 x 的信息。

## 顺序为什么不能换

- **必须先发 t 再出 c**：否则骗子可以先随便选 s，倒推 t = g^s · y^{-c}，等式成立但根本不知道 x。先发 t 把 r 锁死（承诺的 binding 性）。
- **c 必须随机**：考题不可预测，只能真的知道 x 才能当场答出。
- **r 必须一次性**：同一个 r 回答两次挑战 → 私钥直接泄露：

```
s1 = r + c1·x
s2 = r + c2·x
相减: x = (s1 - s2) · (c1 - c2)^{-1} mod q
```

（经典事故：索尼 PS3 ECDSA 复用随机数、比特币早期钱包同款漏洞）

## 三个安全性质

| 性质 | 含义 | 靠什么成立 |
|---|---|---|
| 完备性 | 知道 x 的诚实 A 总能通过 | 指数加法恒等式 g^(r+c·x) |
| 零知识 | B 通过了也偷不走 x | 一个方程两未知数；c 随机 |
| 可靠性 | 不知道 x 的骗子通不过 | 先承诺后挑战的顺序 + 离散对数难 |

可靠性量化：骗子乱蒙 s，等式成立概率 ≈ 1/q ≈ 2^-256。

**特殊可靠性（special soundness）**：能对同一 t 回答两个不同 c 的人必然知道 x（两式相减消去 r 解出 x）。"能过两轮 ⇒ 能算私钥"是零知识证明安全证明的标准套路。

## 转成签名：Fiat-Shamir 变换

交互式协议要求 B 在线发 c；签名时 B 不在场，用哈希冒充挑战：

```
c := H(t ‖ y ‖ m) mod q
签名 = (t, s)，验证仍是 g^s ≡ t·y^c
```

安全要求不变：c 依赖 t（先有 t 才有 c），"先选 s 后补 t"的作弊路径依然被顺序卡死。

## 和 RSA 对比（为什么新协议选 Schnorr）

- 同等 128 位安全：RSA 公钥 3072 bit / 签名 384B vs 曲线版 256 bit / 64B
- **线性结构 s = r + c·x** → 多签聚合成一个（MuSig2）、门限签名（FROST）、批量验证——RSA 做不到
- 无填充方案，没有 Bleichenbacher 那类填充攻击面
- RSA 优势只在验签快、不需要可信参数
