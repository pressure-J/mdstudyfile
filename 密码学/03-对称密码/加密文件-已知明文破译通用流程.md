# 加密文件 · 已知明文破译通用流程

**触发特征**：题目给一个 `.docx/.png/.pdf/.zip`，打开报错（`不是有效的 zip`、图片裂掉、十六进制看是一片乱码），题面说"某加密系统对 office 文档加密，现获取其密报，分析规律求加密算法"。

**一句话打法**：不认识密文 → 用**明文魔数当已知明文**反推变换 → 用**结构完整性（CRC/可解压/尾部标记）**验证。跟密码学原理无关，是"识别模型 + 拟合参数"。

---

## 一、常见文件的已知明文（照抄当字典）

| 类型 | 开头字节（hex） | 稳定字段 | 备注 |
|---|---|---|---|
| zip / docx / xlsx / jar / apk | `50 4B 03 04 14 00` | 前 6 字节 | 后 2 字节 flags **会变**（实测本机三个 zip 家族文件分别是 `02 08` / `00 00` / `06 00`），别写死 |
| zip 结束标记（文件尾） | `50 4B 05 06` | 最后 22 字节整块 | 可用来反推末尾（已知明文也能从尾部取） |
| rar (v5) | `52 61 72 21 1A 07 01 00` | 前 8 | rar4 是 `…1A 07 00` |
| 7z | `37 7A BC AF 27 1C` | 前 6 | |
| gzip | `1F 8B 08` | 前 3 | |
| xz | `FD 37 7A 58 5A 00` | 前 6 | |
| png | `89 50 4E 47 0D 0A 1A 0A` | 前 8（= `\x89PNG\r\n\x1a\n`） | 尾部固定 `49 45 4E 44 AE 42 60 82`（IEND+CRC） |
| jpg | `FF D8 FF E0` | 前 3 稳（`FF D8 FF`），第 4 字节是 `E0/E1/DB` | 尾部 `FF D9` |
| gif | `47 49 46 38 39 61` | 前 6 | |
| pdf | `25 50 44 46 2D`（`%PDF-`） | 前 5 | 尾部 `%%EOF` |
| doc / xls / ppt（97-2003，CFB） | `D0 CF 11 E0 A1 B1 1A E1` | 前 8 | |
| elf | `7F 45 4C 46` | 前 4 | 紧跟 1/2 = 32/64 位 |
| pe / exe / dll | `4D 5A`（`MZ`） | 前 2 | 只有 2 字节，反推时靠别处补 |
| java class | `CA FE BA BE` | 前 4 | |
| sqlite | `53 51 4C 69 74 65 20 66 6F 72 6D 61 74 20 33 00`（`SQLite format 3\0`） | 前 16 | |
| pcap | `D4 C3 B2 A1` | 前 4 | 也可能 `A1 B2 C3 D4`（大端）、`4D 3C B2 A1`（纳秒版） |
| pcapng | `0A 0D 0D 0A` | 前 4 | |
| mp4 / mov | 偏移 **4** 处 `66 74 79 70`（`ftyp`） | 前 8 一起看 | 前 4 字节是块长度，**不是魔数** |
| wav | `52 49 46 46`（`RIFF`）+ 偏移 8 处 `57 41 56 45`（`WAVE`） | 前 12 | |
| tomcat/weblogic 加密文件 | 无固定头 | — | 只能靠尾部/长度推 |

> 以上 hex 全部是本机真文件 `xxd` 抓出来的（`tomcat` 那一行除外，它是经验值，没有固定头）。

**怎么挑已知明文才不浪费**：挑**规范写死、每份文件都相同**的字段（魔数、版本、压缩方法、结尾标记），不要挑时间戳 / CRC / 文件大小 / flags —— 那些每个文件都不一样，硬当已知明文会把候选全排掉。

## 二、模型判别表（先定模型，再谈解密）

| # | 模型 | 密文特征 | 判别动作 |
|---|---|---|---|
| 1 | **单字节变换 `f(p)`**（替换表 / 循环移位 / 异或固定值 / 加常数） | 同明文字节 → 始终同密文字节；字节频次分布整体搬家（`0x00` 变某个字节） | 重复片段**任意对齐、任意距离**；某个字节异常多 |
| 2 | **周期密钥异或** `c[i]=p[i]^k[i%n]` | 同明文字节按位置变不同密文 | **所有重复片段距离的 gcd = n**（gcd>1 且 ≤32 基本就是它） |
| 3 | **ECB 分组** | 相同明文块 → 相同密文块 | 重复段**长度 ≥16 且起点 16 对齐** |
| 4 | **CBC / 带随机 IV 的模式** | 全文件找不到 ≥8 字节的重复段 | 无重复 + 长度是块大小倍数 |
| 5 | **流密码（RC4/CTR/OFB）** | 同上，无任何结构泄露 | 必须有**密钥重用**（两段密文互异或消掉密钥流）或已知明文段才解得动 |

**辅助判据（长度）**：文件长度 `% 16 != 0` 就基本排除"带 PKCS#7 填充的 AES"，`% 8 != 0` 排除带填充的 DES/3DES —— 但注意有些实现用 CTS/截断，所以这是**优先排除**，不是铁律。

**一眼区分 1 和 2**：本题密文里同一个 14 字节在偏移 0 / 436 / 708 / 1104 处原样重复，且**恰好在第 15 字节分叉**（那里开始是 compression 之后的 time/date，每个条目不同）。这说明变换**与位置无关** → 模型 1。若是周期密钥，重复只会出现在距离为周期倍数的位置。

## 三、四步解题流程

### Step 1 量密文（不改文件，先看规律）

```py
import collections
from math import gcd
FILE = r"C:\Users\徐利杰\Downloads\2026-11-04 17_19_31----99fb8034f0d54ac9ab6eddbf7137b9a0.docx"   # ← 换成目标密文
d = open(FILE,'rb').read()
print(len(d), len(d)%8, len(d)%16)
print(collections.Counter(d).most_common(5))

seen, reps = {}, []
for i in range(len(d)-7):                    # 8 字节窗口找重复
    w = d[i:i+8]
    if w in seen:
        if i - seen[w] >= 8: reps.append((seen[w], i))       # 只留不重叠的对，否则距离全是 1..7
    else:
        seen[w] = i
print(len(reps), sorted({j-i for i,j in reps})[:8], gcd(*[j-i for i,j in reps]))
```

这一步产出三个数：**重复段长度最大值 / 距离的 gcd / 起点 mod 16**，直接对上判别表。

### Step 2 拟合变换（用已知明文）

拿魔数当 `p`，密文对应位置当 `c`，逐个字节算 `c ^ p` / `c - p` / `ROL(c,1) ^ p`…，看哪一族能同时对上所有已知字节。**不要靠眼看**，跑脚本。

### Step 3 全文件解密 + 自动评分

解出来的候选可能不止一个（尤其当已知明文只有 4 字节），必须用**外部校验**打分：

| 文件类型 | 校验手段 |
|---|---|
| zip/docx/xlsx | `zipfile.testzip()` → `None` 表示所有 entry 的 **CRC32 全对**（最强证据，CRC 伪造不了） |
| png | 头 8 字节 + 尾部 `IEND` CRC 完整 + `zlib` 解 IDAT |
| jpg | 头 `FFD8FF` + 尾部 `FFD9` |
| pdf | 头 `%PDF-` + 尾部 `%%EOF` + 能否被 pypdf 解析 |
| 通用 | 可打印率、`utf-8` 能否解码、`file` 命令能否认出来 |

**关键教训**：本题用"左移丢最高位"的解也能解出一份**目录结构、文件名全对的 zip**，看着完全像成功，但第一个 entry 一 inflate 就 `invalid code lengths set`。**只有 CRC 全过才算解对。**

### Step 4 抽正文

```py
import zipfile, re
OUT = r"C:\Users\徐利杰\Downloads\decrypted.docx"   # ← 上一步解出来的文件
xml = zipfile.ZipFile(OUT).read('word/document.xml').decode()
print(re.sub(r'<[^>]+>', '', xml).strip())
```

## 四、按模型分打法

**模型 1（本题）**：直接跑 `D:\python\CTF工具箱\crypto\33-加密文件-已知明文反推单字节变换.py`，改 `DATA` / `PT` 两行。它自动枚举 `c = ROL(p,k) ^ b` 与 `c = ROL(p,k) + b`（k=0..7 × b=256），用剩余已知字节校验，再按魔数 + zip CRC 打分。

实测输出（本题密文）：

```text

    字节频次 top5: 5a×559, 4a×98, 5e×97, 84×92, 80×84

    重复段公共前缀长度分布 {8: 36, 9: 29, 11: 26, 10: 26, 13: 21}
    判定：→ 单字节变换 f(p)：重复段任意对齐、任意距离
[2] 用 10 字节已知明文 50 4b 03 04 14 00 02 08 08 00 拟合
    候选 [('xor', 1, 90)]
[3] xor k=1 b=0x5a  head=50 4b 03 04 14 00 02 08  score=30 (魔数命中 zip/docx/xlsx；zip 16 个 entry CRC 全对)
[4] 最优：c = ROL(p,1) ^ 0x5a   → 解密 p = ROR(c ^ 0x5a, 1)
```

**模型 2（周期密钥）**：脚本 33 会返回"候选为空"，此时去跑 `21-循环异或-已知明文前缀推密钥周期.py`，见 `循环异或-已知明文前缀推密钥周期-WriteUp.md`。已知明文足够长（≥ 周期×2）可直接算出每个 `k[i]`；不足就枚举 `n ∈ [1,32]` 看哪个 n 让解出的字节"看起来像该格式"。

**模型 3（ECB）**：找相同 16 字节块 → 已知明文块在密文中的位置 → 若明文里有大量重复块（如 BMP 大色块、明文表单），可以直接搬块伪造；也可对"块内只有少数字节未知"做逐字节字典爆破。

**模型 4（CBC）**：无 oracle 时基本只能靠"首块"——首块 `C1 = E(IV ⊕ P1)`，若 IV 明文已知（或缺省全 0）就用已知明文反推。有"解密后是否合法填充"的反馈才上 padding oracle（见 `26-CBC-PaddingOracle.py`）。

**模型 5（流密码）**：找密钥重用。两段密文异或 = 两段明文异或，用词频/格式魔数拼出两段明文，再 `ks = c ^ p` 得到密钥流，任意长度明文都能伪造（见 `流密码密钥重用.md`）。

## 六、易错点

1. **只凭魔数就宣布胜利** —— 本题错误候选也能凑出 `PK\x03\x04`，靠 CRC 才分得开。
2. **把时间戳/CRC/flags 当已知明文** —— docx 的 flags 实测三种值，签名越"活"的字段越会误导拟合。
3. **循环移位写成普通左移** —— `(p<<1)` 会丢最高位，`ROL(p,1)` 把最高位塞回最低位，两者低 7 位完全一样，只有 CRC 能区分。
4. **拿 Python 的 `>>`/`<<` 直接当 ROL** —— 必须 `& 0xFF` 且补回卷位，否则 int 无限位宽会错。
5. **只看文件长度不整除就断言"不是分组密码"** —— 有 CTS/截断实现，这条只是优先排除。
6. **忘了密文尾部也是已知明文** —— zip 的 EOCD（`50 4B 05 06` + 18 字节）、png 的 IEND 都在文件尾，头部解不出来时可以倒着来。
