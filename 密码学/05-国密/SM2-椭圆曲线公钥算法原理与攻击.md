# SM2 椭圆曲线公钥算法：原理与攻击

国密**椭圆曲线公钥密码算法**，标准号 **GM/T 0003**。曲线固定为 256 位素域曲线，支持**签名、密钥交换、公钥加密**三种功能。对标 ECDSA/ECDH/ECIES，但**三处关键设计不同**（见第 3 节）。

## 2. 算法原理

### 2.1 曲线参数（固定不可换）

曲线方程 $y^2 = x^3 + ax + b \pmod p$：

| 参数 | 值（十六进制） |
|------|----------------|
| p | `FFFFFFFE FFFFFFFF FFFFFFFF FFFFFFFF FFFFFFFF 00000000 FFFFFFFF FFFFFFFF` |
| a | `FFFFFFFE FFFFFFFF FFFFFFFF FFFFFFFF FFFFFFFF 00000000 FFFFFFFF FFFFFFFC` |
| b | `28E9FA9E 9D9F5E34 4D5A9E4B CF6509A7 F39789F5 15AB8F92 DDBCBD41 4D940E93` |
| n | `FFFFFFFE FFFFFFFF FFFFFFFF FFFFFFFF 7203DF6B 21C6052B 53BBF409 39D54123` |
| Gx | `32C4AE2C 1F198119 5F990446 6A39C994 8FE30BBF F2660BE1 715A4589 334C74C7` |
| Gy | `BC3736A2 F4F6779C 59BDCEE3 6B692153 D0A9877C C62A4740 02DF32E5 2139F0A0` |

**识别要点：$a = p - 3$**（不像 secp256k1 的 $a=0$）。$p$ 与 $n$ 都是 256 位素数。

**安全强度**：256 位曲线 → 离散对数问题需 $\approx 2^{128}$ 次运算，等价 AES-128。比 RSA-2048（$\approx 2^{112}$）更强。

### 2.2 身份标识 ZA（SM2 特有）

签名与密钥交换都不是直接哈希消息，而是哈希 **ZA ‖ M**：

$$Z_A = SM3(ENTL \| ID \| a \| b \| G_x \| G_y \| P_x \| P_y)$$

| 字段 | 说明 |
|---|---|
| $ENTL$ | ID 长度的 **2 字节大端**（默认 ID `1234567812345678`，16 字节 → `0x0080`） |
| $ID$ | 签名者身份标识（默认 `1234567812345678`） |
| $a,b,G_x,G_y$ | 曲线参数（固定） |
| $P_x,P_y$ | **签名者公钥坐标** |

**作用**：把签名者身份绑进哈希，防止**公钥替换攻击**。这是 SM2 相对 ECDSA 的核心安全增益——同一私钥换一个 ID，ZA 就变，签名不可跨身份复用。

### 2.3 数字签名

**签名**（私钥 d，消息 M）：

1. $e = SM3(Z_A \| M)$
2. 取随机数 $k \in [1, n-1]$
3. $(x_1, y_1) = kG$
4. $r = (e + x_1) \bmod n$　　若 $r = 0$ 或 $r + k = n$ 则重新取 k
5. $s = (1+d)^{-1} \cdot (k - r\cdot d) \bmod n$　　若 $s = 0$ 则重新取 k
6. 签名 = $(r, s)$

**验签**（公钥 P）：

1. 检查 $r, s \in [1, n-1]$
2. $e = SM3(Z_A \| M)$
3. $t = (r + s) \bmod n$　　若 $t = 0$ 则无效
4. $(x_1', y_1') = sG + tP$
5. 校验 $R = (e + x_1') \bmod n$ 是否等于 $r$

**验签为什么成立**：代入 $s = (1+d)^{-1}(k - rd)$、$t = r + s$ 可推出 $sG + tP = kG$，故 $x_1' = x_1$，$R = r$。

### 2.4 公钥加密（C1C3C2 结构）

**加密**（公钥 P，明文 M）：

1. 取随机数 $k \in [1, n-1]$
2. $C_1 = kG$（椭圆曲线点）
3. $(x_2, y_2) = kP$
4. $t = KDF(x_2 \| y_2, \text{klen})$，若 $t$ 全零则重取 k
5. $C_2 = M \oplus t$
6. $C_3 = SM3(x_2 \| M \| y_2)$
7. 密文 = $C_1 \| C_3 \| C_2$

**解密**：由 $C_1$ 用私钥算 $dC_1 = (x_2,y_2)$，复原 $t$ 与 M，再用 $C_3$ 校验完整性。

| 段 | 内容 | 长度 |
|---|---|---|
| C1 | $kG$ | 64 字节（x ‖ y） |
| C3 | $SM3(x_2\|M\|y_2)$ | 32 字节 |
| C2 | $M \oplus KDF$ | = 明文长度 |

**原始密文长度 = 明文长度 + 96 字节。**

**KDF**：$KDF(Z, \text{klen}) = SM3(Z \| ct_1) \| SM3(Z \| ct_2) \| \cdots$，其中 $ct$ 是 32 位大端计数器，从 **1** 开始递增，截取 klen 字节。

> ⚠️ **拼接顺序是 C1C3C2**（老标准 C1C2C3），弄反直接解不开。而且 OpenSSL 输出还要再套一层 DER（下节）。

### 2.5 密钥交换

非简单 DH，而是多轮带校验的 Z 值交换：

1. 双方各生成临时密钥对 $(r_A, R_A)$、$(r_B, R_B)$ 并交换 $R$
2. 计算共享点 $\bar{R} = (x_{\bar R}, y_{\bar R})$，其中 $\bar R = h \cdot t_A \cdot R_B$（$t_A = (d_A + r_A \cdot \overline{x_1}) \bmod n$）
3. 双方各自用 SM3 算共享密钥 $K = KDF(x_{\bar R} \| y_{\bar R} \| Z_A \| Z_B, \text{klen})$
4. 用 $S_1 = SM3(x_{\bar R} \| Z_A \| Z_B)$ 等值校验关键确认

**与 ECDH 的区别**：**绑定了双方身份 ZA/ZB**，且带密钥确认，能防中间人。

## 3. 常见攻击

### 3.1 攻击一：签名随机数 k 重用（最高频）

**检测**：SM2 的 $r = e + x_1$，所以由 $r$ 反推 $x_1 = (r - e) \bmod n$。**两组签名的 $x_1$ 相同 → 同一个 k。**

> ⚠️ **不能像 ECDSA 那样直接看 r**。ECDSA 的 $r = x_1 \bmod n$ 与消息无关，k 重用会**必然导致 r 相同**；SM2 的 $r$ 含消息哈希 $e$，**$r_1 \ne r_2$ 但 $x_1$ 相同**。这是识别两套算法的分水岭。

**推导**（两组签名 $(r_1,s_1)$、$(r_2,s_2)$ 用同一个 k）：

$$
\begin{aligned}
s_1 &= (1+d)^{-1}(k - r_1 d) \\
s_2 &= (1+d)^{-1}(k - r_2 d) \\
\text{相减}:\quad s_1 - s_2 &= (1+d)^{-1} \cdot d \cdot (r_2 - r_1)
\end{aligned}
$$

令 $t = \dfrac{s_1 - s_2}{r_2 - r_1} \bmod n$，则 $t = \dfrac{d}{1+d}$，解得：

$$\boxed{d = \frac{t}{1-t} \bmod n}$$

**反解 k 做自检**：$k = s(1+d) + rd \bmod n$。

**实测结果**：

| 项 | 值 |
|---|---|
| 真实私钥 d | `3945208f...4df7c5b8` |
| 恢复出的 d | `3945208f...4df7c5b8` ✅ 完全一致 |
| $x_1$(第1次) = $x_1$(第2次) | `f6a687ab...f57a89f9` ✅ 判定 k 重用 |
| k（恢复） | `6cb28d99...1fb2f96f` ✅ 与真实 k 一致 |
| 套 ECDSA 公式 $k=(e_1-e_2)/(s_1-s_2)$ | `f344f139...6921536a` ❌ 垃圾值 |

**⚠️ 本节最大考点**：SM2 的 $s = (1+d)^{-1}(k - rd)$ **与 ECDSA 的 $s = k^{-1}(z + rd)$ 形式不同**，照抄 ECDSA 的 k 重用公式得不到任何有用结果。

### 3.2 攻击二：低熵随机数 / 部分比特泄露

若 k 只用了部分比特（如高 8 位为 0、或每次只有低位随机），可归约为**隐藏数问题（HNP）**，用格约简（LLL）求解，与 ECDSA 的同类攻击思路完全一致。所需签名数量与泄露比特数成反比。

**实现层祸根**：用 `random.random()`、时间戳、递增计数器当 k。

### 3.3 攻击三：无效曲线 / 小阶子群

前提是**服务端不校验输入点是否在曲线上**。

- **无效曲线攻击**：投递一个落在弱曲线（阶含小因子）上的点，让私钥运算在弱曲线上进行，求出 $d \bmod \text{小素数}$，再用 CRT 拼回 d。
- **小阶子群攻击**：需要曲线阶 $n$ 含小因子。

**SM2 标准曲线**：$n$ 与 $p$ 都是大素数，**标准参数下这两个攻击不成立**（除非题面换了曲线参数）。所以：

> 遇到这类题先确认三件事：① 点是否做过曲线校验；② $n$ 是否光滑（小因子多）；③ 题面是否换了 a/b/G。

### 3.4 攻击四：加密 nonce 重用（与 OFB 密钥流重用同理）

加密时 $C_1 = kG$、$KDF(kP)$ 都只依赖 k。**同一 k 加密两条消息 → $C_1$ 完全相同，且密钥流相同**：

$$C_2^{(1)} \oplus C_2^{(2)} = M_1 \oplus M_2$$

已知任一明文即可推出另一条（和 SM4-OFB IV 复用是同一类错误）。

**实测**（固定 k 加密两条消息）：

> 密文总长 120 = 明文 24 + 96
> C1_1 = C1_2 (同一个 k): True ✅
> C2_1 ^ C2_2 = 000000000000000003030b5804560e180101534d0408
> P1  ^ P2    = 000000000000000003030b5804560e180101534d0408  ✅ 一致
> 已知 P1 求 P2: b'account=bob;amount=999'  ✅

> 只在 $C_1$ 相同且能看到两条密文时才可利用。真实实现每次取新 k，所以这是**实现缺陷**而非算法缺陷。

### 3.5 攻击五：弱公钥 / 参数替换

- **公钥不可信**：若攻击者能替换公钥，则可伪造签名（ZA 能缓解，但需 ID 固定且校验）。
- **未校验 $P \ne O$**：投递无穷远点等特殊点，可让验签恒通过。
- **未校验 $s$ 范围**：$s = 0$ 或超范围时的边界处理可能被绕。
- **ZA 的 ID 可伪造**：若实现允许攻击者指定 ID，ZA 的防公钥替换作用被削弱。

### 3.6 攻击六：实现层旁路

- **标量乘的时序/功耗**：非恒定时间实现会泄露 k 的比特模式（尤其 `_kg` 这类"遇 1 才加"的双点-点加实现）。
- **缓存命中**：预计算表访问模式泄露标量信息。
- 防御：恒定时间实现、标量盲化、坐标随机化。

## 4. 工具链与实测命令

| 工具 | 能力 |
|---|---|
| OpenSSL 3.5.5 | SM2 密钥对 / 签名 / 验签 / 加解密（本机已实测跑通） |
| Python `gmssl` | `CryptSM2` 的 `sign/verify/encrypt/decrypt/_kg/_sm3_z` |

```bash
# 密钥对
openssl genpkey -algorithm ec -pkeyopt ec_paramgen_curve:SM2 -out sm2.key
openssl pkey -in sm2.key -pubout -out sm2.pub

# 签名 / 验签
openssl pkeyutl -sign   -in p.txt -inkey sm2.key -rawin -digest sm3 -out sig.bin
openssl pkeyutl -verify -in p.txt -sigfile sig.bin -inkey sm2.pub -pubin -rawin -digest sm3

# 加解密
openssl pkeyutl -encrypt -in p.txt -inkey sm2.pub -pubin -out enc.bin
openssl pkeyutl -decrypt -in enc.bin -inkey sm2.key
```

### 4.1 OpenSSL 密文是 DER，不是裸 C1C3C2

实测 13 字节明文的密文是 **120 字节**（不是 109），因为 OpenSSL 把点当 ASN.1 INTEGER、把 C3/C2 当 OCTET STRING：

| DER 元素 | 标签 | 长度 | 对应 |
|---|---|---|---|
| SEQUENCE | 0x30 | 118 | 整体 |
| INTEGER x | 0x02 | 33（高位置 1 补前导 0x00） | C1 前半 |
| INTEGER y | 0x02 | 32 | C1 后半 |
| OCTET STRING | 0x04 | 32 | C3 |
| OCTET STRING | 0x04 | 13 | C2 |

DER 头开销通常 **10~11 字节**，随长度域和高位补零浮动。**别用「明文+96」硬解 OpenSSL 输出**；换 `gmssl` 拿到的才是裸 C1C3C2（实测 13 字节明文 → **109** 字节 = 13 + 96）。

### 4.2 踩过的坑（全部实测复现）

| 坑 | 现象 | 处理 |
|---|---|---|
| 验签缺 `-pubin` | `Could not find private key from sm2.pub` + `unsupported` | 必须显式加 `-pubin` |
| `gmssl` 的 `sign(msg, K)` 必须传 K | `TypeError: sign() missing 1 required positional argument: 'K'` | K 是随机数，必须每次 `os.urandom(32).hex()` 且保密 |
| OpenSSL 3.x 签验要带 `-rawin -digest sm3` | 不带则不做 ZA 预处理，验签失败 | 固定写法 |
| `gmssl` 的 `_sm3_z` 硬编码默认 ID | `0080` + `3132...`（`1234567812345678`） | 题面用非默认 ID 时须自己拼 ZA 重算 e |
| `gmssl` 的 `sign` 不做 ZA | 它签的是裸 `SM3(msg)`：`_sm3_z` 需手动调，或用 `sign_with_sm3` | 看清调的是哪个函数 |
| `gmssl` 的 `_kg` 是"遇 1 才加"实现 | 非恒定时间，有侧信道 | 生产环境不用这套纯 Python 实现 |
| SM2 不能照抄 ECDSA 的 k 重用公式 | 解出垃圾值 | 用 $d = t/(1-t)$ |

## 5. 面试速答卡

**问：SM2 比 ECDSA 好在哪？**
答：① **签名哈希带 ZA**，绑定签名者身份，防公钥替换；② 曲线参数由国标固定，避免参数选择不当的风险；③ 密文结构自带完整性校验 C3；④ 密钥交换带身份绑定与密钥确认。

**问：ZA 是什么，为什么需要它？**
答：$Z_A = SM3(ENTL\|ID\|a\|b\|G_x\|G_y\|P_x\|P_y)$，把签名者 ID 和公钥混入哈希。作用是防公钥替换——同一个签名在不同 ID/公钥下不通用。

**问：SM2 的密文为什么有 96 字节开销？**
答：C1（点，64 字节）+ C3（哈希，32 字节）。

**问：SM2 的 k 重用和 ECDSA 的 k 重用有什么不同？**
答：**ECDSA 看 r 是否相同**（同一 k ⇒ r 相同）；**SM2 不能看 r**，因为 $r = e + x_1$ 含消息哈希，要**反推 $x_1$** 比对。恢复公式也不同（SM2 是 $d = t/(1-t)$）。

**问：SM2 的 256 位曲线相当于多少位 RSA？**
答：$\approx$ RSA-3072；离散对数需 $2^{128}$，等价 AES-128。

**问：SM2 的三种功能分别对标什么？**
答：签名对标 ECDSA、密钥交换对标 ECDH、加密对标 ECIES。
