# Misc 文件格式修复速查（异或 / 宽高 / CRC / 拼接 / 尾部追加）

> 适用：图片打不开、打开了但"缺一块"、文件比同级大一圈、题目 hint 出现"异或/文件头/结构/chunk"。
> 原则：**先看真类型（魔数），再怀疑结构，最后才怀疑内容**。动手前备份原文件。
> 配套：《Misc图片题解题步骤.md》讲整体排查流程与隐写手法，本文只讲"文件结构坏了"怎么修。

---

## 0. 五分钟起手式

1. 看前 16 字节 + 文件大小（010 / `py 03-文件类型识别与strings.py`）
2. 头正常 → 数结构（PNG chunk / ZIP 目录 / JPEG 段）
3. 头不正常 → 猜变换：异或、加减、取反、头被挪位
4. 结构正常 → 查"被改大的宽高 / 坏 CRC / 尾部追加 / 第二个头"
5. 全正常 → 转向隐写（LSB / steghide / 压缩域）

---

## 1. 魔数对照表（判断真类型只信这个，不信扩展名）

| 类型 | 头 | 尾/关键标记 |
|---|---|---|
| PNG | `89 50 4E 47 0D 0A 1A 0A` | 末尾 `IEND` 块 |
| JPEG | `FF D8 FF` | `FF D9` |
| GIF | `47 49 46 38` (`GIF8`) | `3B` |
| BMP | `42 4D` (`BM`) | 头里写宽高 |
| ZIP | `50 4B 03 04` | EOCD `50 4B 05 06`（空包 `50 4B 05 06` 直接开头） |
| RAR4 | `52 61 72 21 1A 07 00` | 无尾标记 |
| RAR5 | `52 61 72 21 1A 07 01 00` | 无尾标记 |
| 7z | `37 7A BC AF 27 1C` | 无尾标记 |
| GZIP | `1F 8B 08` | 无尾标记 |
| PDF | `%PDF` | `%%EOF` |
| ELF | `7F 45 4C 46` | — |
| PE/exe | `4D 5A` (`MZ`) | — |
| tar | 偏移 257 处 `ustar` | — |

**变换类"头坏了"的四种可能**：整文件异或固定值 / 整文件逐字节 +n / 按位取反（`0xFF - b`）/ 头部若干字节被换位置。

## 2. 整文件异或：值不用猜

```python
key = data[0] ^ 0x89          # PNG；ZIP 用 0x50，RAR 用 0x52，PDF 用 ord('%')
fixed = bytes(b ^ key for b in data)
```

判据（拿一组比一遍就能看出是哪种变换）：

| 现象 | 变换 |
|---|---|
| 每个字节都差同一个值 | 单字节异或 `^ k` |
| 差值逐字节递增/递减 | 逐字节加偏移 `+i` |
| 高半字节规律、低半字节乱 | 只异或了某一字节位，或周期异或 |
| `f8 00 00 00` 之类扎堆 | 常见周期 key：`02 1A 00 00`、`0D 0A 1A 0A` |

- **必须整份文件都异或**，只异或头等于没修（chunk/IDAT 全乱）。
- 周期异或（key 比 1 字节长）：拿已知明文前缀反推 → `key[i] = ct[i] ^ pt[i]`，再求最小重复周期（工具箱 `crypto/21-循环异或-已知明文前缀推密钥周期.py`）。
- 修完立刻验证三件事：**魔数对 / 结构能解析 / CRC 或解压长度自洽**。

## 3. PNG：八成"结构类"题都在这里

结构 = 8 字节签名 + 若干 chunk：

```
[长度4][类型4][数据 N][CRC4]      ← 全部大端
CRITICAL: IHDR / PLTE / IDAT / IEND
辅助: pHYs / tEXt / zTXt / iTXt / tIME / gAMA
```

**五种经典篡改，逐条查：**

| 现象 | 病因 | 处理 |
|---|---|---|
| 打不开 / zlib 报错 | 宽高被改大或改小 | 反推真实高度（见下公式），改回并**重算 CRC** |
| 只看得到图的上半截 | 高度被改小，下半截还在 IDAT 里 | 同上，把高改大 |
| 有第二个 `IHDR` | **两张 PNG 被 `copy /b` 拼在一起**，第二张缺签名 | 从第二个 IHDR 偏移切到文件尾 + 补 `89 50 4E 47 0D 0A 1A 0A` |
| 文件比图大很多 | `IEND` 之后有追加数据 | 按 IEND 切尾，看是不是 ZIP/RAR/另一个 PNG |
| IDAT 解压后比图需要的长 | IDAT 尾部塞了额外数据 | `zlib.decompressobj()` 解到 `eof`，剩余部分就是货 |

```python
# 反推真实高度：每行 1 字节 filter + W × 通道数 × 位深/8
raw = zlib.decompress(idat)                  # 多块 IDAT 先拼起来
row = 1 + W * (4 if color_type == 6 else 3 if color_type == 2 else 1) * depth // 8
real_h = len(raw) // row                     # 整除不了 = 还塞了别的东西，看余数
# 验 CRC：crc32(类型+数据) 必须等于存的 CRC；被改的块 CRC 一定不匹配，这就是线索
```

排查顺序（照抄）：
1. 列 chunk（长度/类型/CRC 是否 ok）→ 有没有第二个 IHDR、有没有 IEND、IEND 后还有没有字节
2. 有坏 CRC → 那个块就是被改的地方（常见是 IHDR）
3. 解 IDAT → 长度对不对、`unused_data` 有没有东西
4. 文本块（tEXt/iTXt/zTXt）逐个 dump，base64 常在这儿
5. 都没问题 → 转 LSB / 调色板索引 / 隐写

## 4. JPEG

- 头 `FF D8 FF`，尾 `FF D9`。
- 尾部追加：找 **SOI 之后第一个 `FF D9`**，别用 `rfind`（内嵌 ZIP 里会再冒 `FF D9`）。
- 段结构 `FF 标记 长度 数据`：`FFE0` JFIF / `FFE1` EXIF（缩略图、注释）/ `FFFE` 注释。
- 多个 `FF D8` = 里面拼了多张图，逐个 SOI..EOI 切。
- JPEG 的 LSB 慎用（有损），隐写优先 `steghide`、DCT 系数、EXIF 缩略图。

---

## 5. ZIP（伪加密 / 追加 / 坏 CRC）

| 判据 | 结论 | 处理 |
|---|---|---|
| 压缩方法 = store 且 压缩大小 == 原始大小 | **伪加密** | CDH 标记位 `01 08` → `00 08` |
| 压缩大小 ≈ 原始大小 + 12 | 真 ZipCrypto 加密 | 去找密码（提示常在图片/注释里），别硬爆 |
| `7z` 打不开、尾部有一堆垃圾 | 中央目录被挤坏 | 按 LFH（`PK\x03\x04`）手工 carve 条目 |
| `Bad CRC-32` 但能读 | 出题人故意填坏 CRC | 按 LFH 手工 carve，跳过 CRC 校验 |
| 打开就是乱码目录 | 编码 GBK | `chcp 936` / `unzip -O cp936` |

LFH 数据起点 = `30 + 名字长度 + **扩展字段长度**`（漏了扩展字段长度会让后面全错位且不报错）。注释在 EOCD 之后，一行 `zipinfo -z` 看最快。

## 6. 其他容器

- **RAR**：头部长度字段常不可信（实测声明 5096 而文件只有 196 字节），**切到文件尾** 反而能打开。
- **7z / GZIP**：只能切到文件尾，别精确定尾。
- **BMP**：头里直接写宽高（偏移 18/22），改宽高类题比 PNG 多；像素数据起点 = 比特数组偏移。
- **GIF**：逻辑屏幕描述符宽高在偏移 6/8；多帧图注意每帧的图形控制块。
- **PDF**：`%%EOF` 之后可追加；对象流里藏附件（`/EmbeddedFile`）。

## 7. 现象 → 先查什么

| 你看到 | 先查 |
|---|---|
| 打不开，头不对 | 整文件异或/加法/取反（第 2 节） |
| 能打开但显示不全 | 宽高被改（PNG/BMP/GIF 头里都是明文宽高） |
| 比正常图大很多 | IEND/EOI 之后追加数据 |
| 只露出一半图 | 高度改小，下半截在 IDAT 里 |
| 里面有两张图 | 搜第二个魔数（俩 IHDR / 俩 FFD8） |
| chunk 有坏 CRC | 坏的那个块被改过，重点看 IHDR |
| 图完全正常但题没线索 | 转隐写：LSB / steghide / 文本块 / 调色板 |

## 9. 一句话总结

**Misc 的"文件坏了"类题，90% 是出题人只动了一两个字节或一两个块**：头异或了 → 看魔数推回去；宽高改了 → 用 IDAT 长度反推；块被改 → CRC 对不上就是线索；拼了双图 → 数魔数个数；塞了尾巴 → 找结束标记。把这五条走一遍，绝大多数能出图或出压缩包。
