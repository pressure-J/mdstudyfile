# 密码协议 · 考场速查卡（比赛专用）

> 只背这一页。判型靠表，答题靠三句话。

## 一、TLCP（GM/T 0024）握手顺序

```
C→S  ClientHello        明文：套件清单 + 32B random
S→C  ServerHello        明文：选定套件 + 32B random
S→C  Certificate        服务器证书链（SM2 证书）
S→C  ServerKeyExchange  ①有临时公钥=协商 ②只有签名=传输
S→C  CertificateRequest （出现即"双向认证"）
S→C  ServerHelloDone
C→S  Certificate        客户端证书（双向时）
C→S  ClientKeyExchange  ①65B 点=协商 ②SM2 密文=传输
C→S  CertificateVerify  客户端签名（证明持私钥）
C→S  ChangeCipherSpec → Finished（加密）
```

## 二、套件码表

| 套件码 | 名称 | 密钥交换 | 前向保密 |
|---|---|---|---|
| 0xE011 | ECDHE_SM4_CBC_SM3 | 协商（SM2 密钥交换协议） | 有 |
| 0xE013 | ECC_SM4_CBC_SM3 | 传输（SM2 公钥加密预主密钥） | 无 |
| 0xE015 | ECDHE_SM4_GCM_SM3 | 协商 | 有 |
| 0xE017 | ECC_SM4_GCM_SM3 | 传输 | 无 |
| 0x1301/1302/1303 | TLS1.3 的 AES128/AES256/ChaCha20 | 一律 ECDHE | 有 |

## 三、判型速查（看包 30 秒）

| 看到什么 | 判定 |
|---|---|
| SKE 里有 65 字节 `04‖X‖Y` | 密钥协商（ECDHE） |
| SKE 只有 DER 签名、无密钥参数 | 密钥传输（ECC） |
| CKE 载荷是 65 字节 EC 点 | 协商：客户端临时公钥 |
| CKE 载荷 `30 81 xx` → 02 20/02 20/04 20/04 30 | 传输：SM2 密文 C1x‖C1y‖C3(32)‖C2(48) |
| 出现 CertificateRequest | 双向认证 |
| 无 CertificateRequest | 单向认证 |
| 记录版本 0x0101 | TLCP（不是国际 TLS） |
| ContentType 22/20/23 | 握手 / CCS / 应用数据 |

## 四、必背数字

| 项 | 值 |
|---|---|
| 预主密钥 pre_master_secret | **48 字节**（ECC 模式由**客户端**生成） |
| 主密钥 master_secret | 48 字节（SM3-PRF 派生） |
| SM2 密文结构 | C1(64) + C3(32) + C2(明文长) |
| EC 点编码 | 65 字节 = 04‖X(32)‖Y(32) |
| SM3 摘要 / 随机数 | 32 字节 |
| SM2 签名 DER | 约 70–72 字节（02 20 r, 02 21 00 s） |
| 数据 1 套件码偏移 | 帧1 文件偏移 0x70–0x71 = `e0 11` |

## 五、SM2 密钥交换（GM/T 0003.3）

- $w=\lceil \log_2 n/2 \rceil-1$，$\bar x=2^w+(x \bmod 2^w)$
- $t_A=(d_A+\bar x_1 r_A) \bmod n$，$t_B=(d_B+\bar x_2 r_B) \bmod n$
- $U=[h\,t_A](P_B+[\bar x_2]R_B)=[h\,t_A t_B]G$，$V$ 对称，SM2 曲线 $h=1$
- $K=\mathrm{KDF}(x_U\|y_U\|Z_A\|Z_B)$
- **判断口诀**：U/V 必须"双方私钥 + 双方随机数"才能算；只知道 U 这个点反推 $t_B$ 是 ECDLP，做不到。

## 六、三句话答题模板

1. **证书作用**：证书只做"身份认证 + 签名"，不参与会话密钥传递（唯一例外：TLS1.2 的 RSA 密钥传输模式，代价是没有前向保密）。
2. **密钥交换分类**：密钥传输（RSA / ECC，无 PFS）vs 密钥协商（DH/ECDH/SM2 KE，有 PFS）vs 密钥封装（KEM）。
3. **流量能看出什么**：握手明文段能拿到套件码、DH 组、算法清单、1.2 的证书；会话密钥拿不到；TLS1.3 把证书和签名都加密，可分析面最小。

## 七、其他协议一行速记

| 协议 | 密钥交换在哪 | 证书/身份 | 明文字段能看到 |
|---|---|---|---|
| TLS 1.2 | ClientKeyExchange（RSA 或 ECDHE） | X.509 + CertificateVerify | 套件码、曲线、证书全文 |
| TLS 1.3 | key_share（ECDHE） | CertificateVerify（已加密） | 套件码、group（key_share 32B=X25519 / 65B=P256） |
| IPSec/IKEv2 | IKE_SA_INIT 的 KEi/KEr | IKE_AUTH 用证书签名或 PSK | SA 提议（加密/PRF/DH 组） |
| SSH | KEXINIT 后的 DH/ECDH | 主机密钥 known_hosts（TOFU），用户密钥另算 | 版本串 + KEXINIT 算法清单 |

## 八、高频判断（正=√ 错=×）

1. 套件码里带 ECDHE ⇒ 有前向保密 √
2. ECC 模式下预主密钥由服务端生成 ×（客户端生成）
3. 预主密钥长度 48 字节 √
4. 不知道私钥也能由双方随机数算出 U ×
5. 不校验证书时 ECDHE 仍能防中间人 ×
6. 看到 CertificateVerify ⇒ 双向认证 √
7. 数据 1 的 CKE 里是服务端临时公钥 ×（客户端）
8. 证书里含对称会话密钥 ×
9. IPSec ESP 属于网络层 √
10. SSH 主机密钥和用户密钥是同一套 ×

## 九、现场命令

```bash
# 套件码
tshark -r x.pcap -Y tls.handshake.ciphersuite -T fields -e frame.number -e ip.src -e tls.handshake.ciphersuite
# 握手消息清单
tshark -r x.pcap -Y tls.handshake.type -T fields -e frame.number -e tls.handshake.type
# 看某个消息的原始字节
tshark -r x.pcap -Y "frame.number==7" -x
```
Wireshark 树路径：`Transport Layer Security > TLCP Record Layer > Handshake Protocol > Client Hello > Cipher Suites`
过滤器：`tls.handshake.ciphersuite == 0xe011`（**没有 tlcp.* 字段**）
